Abstract

Conventional Applicant Tracking Systems (ATS) rely on static keyword-matching, producing misaligned hires and systematically filtering out 75% of qualified candidates before human review (Gallup, 2023). AI Talent Match addresses this with a fully integrated multi-agent intelligent recruitment platform built on Django 4.x, powered by Google Gemini 2.5 Flash, and continuously optimized through Reinforcement Learning weight adaptation.

The system computes multi-dimensional match scores across six feature axes, executes a 7-step Autonomous Recruitment Agent per application, conducts AI-proctored interviews with per-answer live scoring, and continuously re-weights feature importance from hiring outcomes. Evaluation across 5 student profiles, 3 companies, and 8 job postings demonstrates 17 ms/match, reliable agent decisions with natural-language explanations, and effective anti-cheat enforcement.

3. Methodology
3.1 Feature Vector & Weighted Match Score

Each student–job pair is encoded into a normalized 6-dimensional vector φ = [f₁…f₆], fᵢ ∈ [0,1], and a weighted dot product produces the final match percentage:

Feature Definitions (fᵢ ∈ [0, 1])
f₁ = cgpa / 4.0 // Academic performance normalised f₂ = |skills ∩ job_req| / |job_req| // Skill coverage ratio f₃ = min(years_exp, 5) / 5 // Work experience (capped at 5 yrs) f₄ = min(n_projects, 5) / 5 // Portfolio depth (capped at 5) f₅ = applications_completed / 10 // Platform activity signal f₆ = trust_score / 100 // Trust / fraud index
Weighted Match Score S(s, j)
S(s, j) = 100 × Σi=16 wᵢ · fᵢ // Σwᵢ = 1 (weights sum to 100%) Initial: w = [0.20, 0.20, 0.20, 0.15, 0.10, 0.15]
3.2 Reinforcement Learning Weight Adaptation

After each hire/reject event the RL weight agent fires a policy-gradient update. Features correlated with successful hires accumulate higher weight over time:

Policy Gradient Weight Update
wᵢt+1 = wᵢt + α · δ · (fᵢ - 0.5) α = 0.05 // Learning rate δ = +1 // Hire → reinforce δ = −1 // Reject → penalise
Post-Update Normalisation
wᵢ ← max(wᵢ, 0.02) // Floor clamp (no weight dies) wᵢ ← wᵢ / Σwⱼ // Re-normalise → Σwᵢ = 1
3.3 Trust Score & Fraud Detection
Trust Score Calculation
T = 100 − Σk pₖ · sₖ sₖ ∈ {low, medium, high} // Fraud flag severity pₖ ∈ {5, 10, 20} // Penalty weight per severity
3.4 AI Interview Anti-Cheat Protocol
3-Strike Violation Policy
V = tab_switches + fullscreen_exits + copy_pastes if V ≥ 3 → auto_submit(flag=CHEATING)
Answer Scoring via Gemini
score = Gemini(question, good_keywords, student_answer) score ∈ [0, 10] → Feedback + Reason returned

6. Conclusions
  • 🚀 17 ms/match proves viability for real-time high-volume screening without batching delays.
  • 🔁 RL weight adaptation demonstrably shifts CGPA (+6%), Trust (+3%), Activity (+3%) after hire signals.
  • 🤖 7-step agent produces explainable, auditable decisions with full Gemini reasoning — no black-box.
  • 🛡️ 3-strike anti-cheat reliably separates strong (7/10) from weak (2/10) under proctored conditions.
  • 📊 Skill gap engine reveals Excel, Python & Docker as top unmet demands — directly actionable for HR.
⚠️
7. Limitations & Future Work
Small evaluation set: 5 candidates / 8 jobs. Production requires 1,000+ applicants to validate RL convergence.
LLM latency: Gemini calls take 1.4–2.1 s; total pipeline ~4 s when LLM is included.
Anti-cheat bypass: VM-based or phone-assisted cheating is undetected by browser JS alone.
Future: PDF CV parsing → structured JSON · Video sentiment scoring · Federated RL across companies
